## Build configuration

Inspected `optee/atf_and_optee_README.txt` and `optee_src_build.sh`.

- Official command: `./optee_src_build.sh -p t234 -t`; `-t` enables fTPM.
- Requires `CROSS_COMPILE_AARCH64_PATH`, AArch64 GCC, and pkg-config.
- `UEFI_STMM_PATH` must point to an existing StMM image; the source archive alone does not supply all official build inputs.
- Uses `PLATFORM=tegra` and `PLATFORM_FLAVOR=t234`.
- Builds OP-TEE and the TA development kit first, followed by the client, samples, and fTPM.
- Sets `CFG_TA_MEASURED_BOOT=y` and `CFG_USE_PLATFORM_EPS=y` for fTPM.
- Embeds fTPM and ftpm-helper as Early TAs, then rebuilds OP-TEE including StMM.
- T234 links `optee/optee_os/prebuilt/t234/libcommon_crypto.a`.
- ATF is in a separate `atf_src.tbz2`; final TOS image generation also requires `gen_tos_part_img.py` from the BSP.

The OP-TEE default version in `mk/config.mk` is 4.2.
fTPM sources reside in `optee/samples/ms-tpm-20-ref/Samples/ARM32-FirmwareTPM/optee_ta/`.
This distribution declares `SPEC_VERSION 162` at `TPMCmd/tpm/include/TpmTypes.h:295`.
Do not apply Revision 1.59 from the official R36.4.4 comparison to this distribution.
The exact upstream commit was not identified; use the distribution archive hash as the baseline.

## Hardware dependencies and boundaries

| Function | Source evidence | Findings |
| --- | --- | --- |
| Tegra platform | `optee/optee_os/core/arch/arm/plat-tegra/conf.mk` | Enables Fuse, SE, SE RNG1, Jetson user key PTA, and TCU; T234 has a 12-core configuration and Pointer Authentication |
| Fuse reads | `optee/optee_os/core/drivers/tegra/t234/tegra_fuse.c` | Reads BSI and security mode through MMIO; initializes ECID and SN |
| Device identifiers | `optee/optee_os/core/drivers/tegra/common/tegra_driver_fuse.c` | Derives ECID from vendor/fab/lot/wafer/coordinates, and SN from ODMID0/1 and ODM_INFO |
| Seed handoff | `optee/optee_os/core/pta/tegra/jetson_ftpm_helper_pta.c` | Reads `nvidia,ftpm-seed`, firmware ID private key, and certificate from DT |
| EPS derivation | Same file, `get_prop_endorsement_seed()` | Uses HKDF-SHA256, checks Fuse SN against EKB SN, and uses EKB EPS_Seed |
| EKB and storage keys | `optee/optee_os/core/pta/tegra/jetson_user_key_pta.c` | Contains paths using OEM_K1/OEM_K2 SE key slots |
| TPM NV persistence | fTPM `platform/NVMem.c` | Uses OP-TEE persistent objects with `TEE_STORAGE_PRIVATE` |

The official Tegra configuration disables RPMB FS.
REE FS persistence is a possible starting point, but its encryption keys must also be managed as state belonging to the same virtual device.

## Existing unfused-device path

`optee/samples/ftpm-helper/host/tool/README_keylime_TPM_for_unfused_Jetson.md`
describes using `ftpm_sim_provisioning_tool.sh` on unfused hardware.
It does not provide a QEMU machine or eliminate Tegra dependencies.

In fTPM `platform/EPS.c`, failure to obtain OP-TEE's `com.microsoft.ta.endorsementSeed` property causes a random EPS to be generated.
The Helper PTA also returns successful initialization while marking provisioning unsupported when DT/EKB inputs are unavailable.
This suggests basic TPM testing and Fuse-derived device identity testing could be staged separately.
Neither overall OP-TEE boot on QEMU nor correct persistence has been verified.

The PTA contains conditional code for `CFG_JETSON_FTPM_HELPER_INJECT_EPS`, but the official build script does not enable it.
Its initialization and invocation paths remain unverified, so it is not selected.

## License findings

- OP-TEE OS's base license, Fuse drivers, ftpm-helper, and other components have BSD-family notices.
- ms-tpm-20-ref uses Microsoft's BSD license; individual file terms still need review.
- `optee/optee_os/LICENSE.NVIDIA` lists two CCC headers and `libcommon_crypto.a` under separate terms.
- The unfused-device Keylime README is marked `LicenseRef-NvidiaProprietary`.

Do not treat the entire package as BSD-licensed.
Only investigation documentation was added, without republishing NVIDIA archives, binaries, or full individual documents.
Manage originals by official URLs and hashes, and check terms for each file before importing it.

## Implementation implications

Keeping NVIDIA sources unchanged requires investigating and reproducing not only Fuse, but SE/RNG, console, boot memory/DT, and the ATF handoff.
It is not established that adding Fuse to virt is sufficient.

The next step at this stage was to obtain the toolchain and BSP StMM and **complete an unmodified T234 build**.
Use the resulting artifacts and dependency list to decide which behavior belongs in QEMU and which minimal platform adaptations might be necessary.
GPU implementation is unnecessary.
