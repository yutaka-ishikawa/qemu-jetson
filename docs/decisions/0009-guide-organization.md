# 0009: 新規構築・通常利用・テスト・更新の文書分離

日本語 | [English](../en/decisions/0009-guide-organization.md)

状態：ユーザーがAを選択済み。

| 候補 | 内容 | 評価 |
| --- | --- | --- |
| A（採用） | build-install / runtime-guide / test-guide / upgrade-guideの4文書へ分離 | 新規構築者が既存ディスクの修正手順を実行せずに進められる |
| B | ビルド文書とテスト文書だけを維持し、通常利用と更新を同じ文書の節にまとめる | 文書数は少ないが、今回問題になった新規/既存手順の混同が残る |

候補Aはユーザーへ提示して承認されたもの。候補Bの整理は比較を明示するための記述で、採用していない。

- build-install.md：新規clone、依存関係、ツールチェーン、ビルド、初期データ、rootfs/ディスク、DTB生成まで。
- runtime-guide.md：構築済み環境での初回ユーザー・公開鍵登録と通常利用。例のユーザー名はユーザー指定のcradsec。
- test-guide.md：firstからbound再起動までのテスト実行・成功判定。
- upgrade-guide.md：既存環境の再ビルド・overlay適用・不足パッケージ導入・過去の不具合修正/復旧。

同じ分担で日英を維持し、READMEとmanから各入口へ案内する。
新規rootfsに含まれるruntimeパッケージを、初回アカウント登録の際に再導入させない。
既存ユーザー・鍵・ディスクは更新で再作成しない。
