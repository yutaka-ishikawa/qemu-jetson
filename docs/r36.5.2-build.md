## 実行手順

以下は実際に使った作業ディレクトリ構成。配布物はリポジトリ外に保存している。

```text
/workspace/work/nvidia-r36.5.2/
├── optee/                     # 内包OP-TEEアーカイブの展開先
├── toolchain/aarch64--glibc--stable-2022.08-1/
├── Linux_for_Tegra/bootloader/standalonemm_optee_t234.bin
├── host-tools/usr/bin/dtc      # dpkg-deb -xで展開
└── venv/
```

venvは `python3 -m venv` で作成し、上記requirementsのパッケージを導入する。
DTCを通常のパッケージ管理で導入できるホストでは、専用host-toolsは不要。

実行したビルドコマンド：

```bash
export CROSS_COMPILE_AARCH64_PATH=/workspace/work/nvidia-r36.5.2/toolchain/aarch64--glibc--stable-2022.08-1
export UEFI_STMM_PATH=/workspace/work/nvidia-r36.5.2/Linux_for_Tegra/bootloader/standalonemm_optee_t234.bin
export PYTHON3_PATH=/workspace/work/nvidia-r36.5.2/venv/bin/python3
export PATH=/workspace/work/nvidia-r36.5.2/host-tools/usr/bin:/workspace/work/nvidia-r36.5.2/venv/bin:$PATH
cd /workspace/work/nvidia-r36.5.2/optee
./optee_src_build.sh -p t234 -t > ../build.log 2>&1
```

公式スクリプトは対象のbuild／installディレクトリを削除してから構築する。
再実行する際は、残したい成果物を別に保存しておく。

## 結果と検証

公式スクリプトは終了コード0、末尾に `optee sources compiled successfully.` を出力。
ソースアーカイブの通常ファイル4,214件について展開先と内容を比較し、変更0、欠落0。
新規生成されたbuild／installファイルはこの比較の対象外。

`file` でOP-TEEの `core/tee.elf` とfTPM TAのELFがAArch64であることを確認。
生成されたconf.mkには以下が含まれる。

```make
CFG_CORE_TPM_EVENT_LOG=y
CFG_EARLY_TA=y
CFG_JETSON_FTPM_HELPER_PTA=y
CFG_WITH_STMM_SP=y
```

最終OP-TEEのリンクマップで、fTPMのUUID
`bc50d971-d4c9-42c4-82cb-343fb7f37896` とHelper TAのUUID
`a6a3a74a-77cb-433a-990c-1dfb8a3fbc4c` のEarly TAオブジェクトを確認。

主な成果物（以下のパスは展開先の `optee/` からの相対パス）：

これらは今回の成果物の識別値。別環境でのビット単位の再現性は未検証。
ビルドログにはtee-raw.binのmakeルール上書きに関する警告が計4行あった。
Tegra固有link.mkと共通link.mkのルール競合で、スクリプトは正常終了した。

`xtest` はビルドしただけで実行していない。QEMUでの起動、TPMコマンド、NV保存、
eFuse相当の機能、実機との同等性も未検証。生成バイナリと第三者ソース原本は公開リポジトリへ追加しない。
